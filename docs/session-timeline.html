Session — Sep 22, 2026

Stability & Reliability Sweep

This session started from two boot-blocking bugs reported at the top of the night — an infinite TaskQueue retry loop freezing the app before login, and OAuth sign-in failing outright — and expanded into a broad reliability and accuracy pass once those were resolved, working manually through chat rather than the usual OpenCode briefing workflow.

What was done:

  • Boot-blocking fixes — Exhausted SYNC_ALL_PROSPECTS tasks were never pruned from the queue, looping forever and saturating the JS thread before login; added removeTask() and a session guard. OAuth was failing because flowType: 'pkce' requires crypto.subtle, unavailable in Hermes — switched to implicit flow.
  • GPS/location floods — Diagnosed rapid AppState active/background thrashing (dozens of transitions/second on device) driving both a GPS update flood and, per Sentry, a likely background ANR; added debounce guards on updateGlobalLocation and processQueue. Also fixed updateGlobalLocation silently overwriting a known-good cached city/zip with a hardcoded Houston/Harris placeholder whenever reverse geocoding failed or hadn't resolved yet at cold boot.
  • Capture accuracy — Removed PhotoIngestScreen's manual storefront/card mode toggle in favor of trying card detection first (falls back to storefront) with no user decision required. Found and fixed a real data bug along the way: card-detected addresses were being joined into one string (street+city+state+zip) before normalization, so the splitter dumped the whole blob into streetName; contact names had no path to pocFirst/pocLast at all and were silently dropped.
  • LeadLock ZIP re-acquisition — A resolved ZIP permanently short-circuited the GPS-driven re-resolve effect for the rest of the screen's life, so a rep moving into a new territory needed to force-close and reopen the app to pick up the new ZIP. Removed the stale guard so the existing coordinate-based dedup key does its job on every GPS update, not just the first.
  • Profile restore on login — Traced a misleading "Your profile has been restored" message (fired unconditionally regardless of outcome) back to its real cause: profile fields (name, employee #, role, branch) were only ever read from local AsyncStorage, with no fallback to the existing Supabase profiles table despite that table already being written to on onboarding. Added a pull-on-login fallback and corrected the message to reflect what actually happened.
  • Legal & branding — Privacy Policy and Terms of Use referenced "Joseph Dugger" throughout instead of the LLC; updated all operator/contact references to O-Kay-est Media LLC, new contact email, effective date, and bumped both policy versions to trigger re-acknowledgment.
  • Cleanup — Removed a leftover "TABBED" debug badge on the Settings header and a dead, no-op EXIF-extraction stub in the gallery import flow.

Diagnosed but not yet fixed: a native UnexpectedNativeTypeException: disabled cannot be cast from String to Boolean crash, confirmed via Sentry but not yet localized to a specific screen — needs either React Navigation breadcrumb instrumentation or a live repro session. Territory Manager's 90-day prospect average was found to read live from local storage only, meaning any rep with clearAfterSend enabled on scheduled export has their count history silently corrupted — needs a real design decision (retain-before-delete, source from Supabase instead, or a separate count log) rather than a quick fix.
