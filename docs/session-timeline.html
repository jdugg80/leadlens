Security: API Key Exposure Remediation

This session addressed a critical security issue: EXPO_PUBLIC_ANTHROPIC_API_KEY was compiled into the Android APK in plaintext, extractable by anyone with the binary. Six client-side files called the Anthropic API directly using this exposed key.

What was done:

  • claude-proxy failover — Added getApiKeys() to the claude-proxy Edge Function with primary key from env + secondary from Supabase Vault (anthropic_api_key_secondary via get_secret RPC). Added RETRYABLE_STATUSES = [429, 500, 502, 503, 529] and 400 usage-limit detection with automatic key switching.
  • extract-prospect failover — Ported identical failover pattern to extract-prospect Edge Function.
  • Client-side key removal — Routed 6 direct Anthropic call sites through claude-proxy via supabase.functions.invoke():
    • multiBusinessDetection.js — vision/image calls
    • claudeApi.js — first-choice photo extraction
    • businessCardEnricher.js — kept exponential backoff retry wrapper
    • healthDepartmentService.js — kept rule-based fallback
    • propertyRecordsService.js — kept { success: false } fallback
  • Dead code cleanup — Removed unused ANTHROPIC_API_KEY from buildingPermitsService.js.

Remaining manual steps: Rotate the compromised key in Anthropic Console, remove from app.json/eas.json, new EAS build required.
