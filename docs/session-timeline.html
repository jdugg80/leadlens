Session — Sep 28, 2026

Map Filter Cleanup, Shared Business-Vertical Taxonomy, Feedback Email Alerts & List Management

Continued directly from BETA-70's release the same day. Started as a map-filter audit ("what actually works, what's not, what's wasting space") and grew into a full rebuild of business-type classification, a beta-feedback delivery investigation that turned up a missing notification rather than a broken button, and a new list-management feature.

What was done:

  • Map filter audit & cleanup — Of 14 filter sections, most either did nothing (comparing against fields leads don't carry) or actively hid results (Status used a stale lowercase 'all' that matched nothing). Trimmed to five working controls; every chip now applies only on "Apply Filters" instead of some applying instantly.
  • Search-result pin — The pin the map drops for a searched address or business had no tap handler at all; now opens the same place card as any nearby business.
  • Shared business-vertical taxonomy — The map filter, Prospect Around, and saved-lead classification each kept a separate, disagreeing list of business types. Cross-checked every type against Google's published Places API (New) tables: 124 of 282 entries across the old filter buckets were not real Google types and could never match. Replaced all three with one shared 16-vertical list, classified primary-type-first, with generic response-only types (food, health, finance) never deciding on their own — previously the cause of hospitals landing in "Office" and supermarkets in "Food." Saved leads, which carry no Google types, had been classifying as "Other" across the board, silently hiding from every Business Type filter; they now classify from stored types or a name-based guess.
  • Beta feedback investigation — The feedback button was reported as "going nowhere." It wasn't broken: submissions were reaching Project Scarlett's feedback_reports table the whole time (confirmed via a live test insert and a device submission), but nothing had ever read the table or notified anyone. Built a notify-feedback Edge Function, triggered by a database trigger via pg_net, that emails on every new row — claims each row before sending so it fires at most once, and a failed alert never blocks the tester's submission. verify_jwt is pinned false in config.toml so a future redeploy can't silently disable it.
  • Named Address Lists manager — Lists could be imported but never viewed or deleted. Added a "Your lists" section to Territory Manager showing each list's address count, an expandable address preview, and delete (cascades to addresses; queued leads are unaffected). The delete helper checks rows actually removed rather than trusting a silent no-op — the same false-success pattern audited repeatedly in prior sessions. Also fixed list items with failed geocoding being kept as (0,0) instead of excluded.
  • Cleanup & release — Removed the temporary SearchProbe/TRACE logging added while verifying the classification work, deleted the orphaned unimported duplicate src/utils/TerritoryMapScreen.js (121 KB), and shipped BETA-71.
  • Industry Vertical classification, continued — Wired the taxonomy work above into actual lead records. inferVertical() now tries a lead's stored businessVertical, then Google types, then a name-based guess before falling back to today's behavior — but strictly only when the current value is empty or exactly 'Other'; anything already classified is left alone. Device testing then found two capture paths the fix didn't reach on its own: single-tap capture set no vertical field at all, so Review's blank-state default ('HVAC / Mechanical', an old seller-trade name) survived and never looked like 'Other' to the new logic; and both bulk-add flows (Prospect Around, batch Nearby Search add) computed the correct classification and then discarded it, since neither ever passes through Review where the upgrade runs. Both are fixed; verified end to end on-device with a live Prospect Around batch.

Known issues carried forward: Anyone holding the Project Scarlett anon key can currently read every feedback row, including tester name and email — the read policy has not yet been locked down. Manually-created leads (not from a map capture) still default to the old list's first entry, 'HVAC / Mechanical', on a blank start — flagged twice tonight, not yet acted on. Stage 2 of the taxonomy migration beyond capture (exports, dashboards, the web portal) has not started. Not yet field-verified: bulk address import (route/opportunity), the Google Drive image picker, and a second PDF territory pass. Five EXPO_PUBLIC_ env vars the app reads (Google/OneDrive OAuth client values, enrichment provider) are not set in .env; an unused EXPO_PUBLIC_ANTHROPIC_API_KEY line should be removed.

Session — Sep 26–27, 2026

Server-Side Export Reliability, Real Export Counts, a Codebase Integrity Audit & Territory Map UX

A reliability-first session that began as one request — make the scheduled export work while the app is closed — and turned into three stacked bugs, a new export-history data source, and a project-wide audit that kept finding the same failure pattern in new places (a function reports failure as a return value, and the caller only checks for thrown errors). It closed with a Territory Map UI pass driven by live-device feedback.

What was done:

  • Server-side scheduled export — The export had been failing on every scheduled run, from three independent faults stacked together: the custom template's name reached the server as a UUID, a freshly built Supabase client used its own session storage and OAuth flow so it saw no session, and the settings sync was gated on a local field that never held the real auth ID. None of it was visible — the sync returned { ok: false, reason: 'unauthorized' } as a normal value and the caller only checked for thrown errors, so it logged "synced" every time. Found by instrumenting getSession()/getUser() rather than reading code: the RLS policy was correct, the client simply had no session, and a re-login under the fixed client cleared it. The settings now reach the server; a full unattended scheduled run has not yet been confirmed end to end.
  • Real export counts — Territory Manager's 90-day and weekly counts read from the local queue, so clearing sent leads erased their history — a problem a working server-side export would have made live. Counts now come from a user_activity_events log written by the on-device export, the server-side function, and the manual export screen (whose existing logging had been failing silently because the table never existed). Counts start from the first export after this build; nothing is backfilled, and no real export has been logged against it yet.
  • Enrichment parallelization — Three independent lookups (POC signal, health violations, property records) ran after the entire Places chain for no data reason and now run alongside it. The Places → Comptroller → Contact chain stays sequential on purpose: Contact Enrichment skips paid provider calls when a POC was already found. The speedup itself has not been measured.
  • Codebase integrity audit — Removed ~42 untracked backup files, then swept callers of { ok: false } functions and ran ts-prune. It found three more unchecked-result sites (territory ZIP auto-sync, login pull-sync, LeadLock updates) and two regressions from earlier full-file rewrites: nearest-neighbor route ordering silently dropped in the RoutePreview refactor, and the entire Saved Routes viewer lost from Territory Manager (the data was intact; Delete was added, since it never existed).
  • Territory import fixes — ZIP+4 addresses never matched territory ZIPs because a global regex match returned the whole "77566-5248" instead of the 5-digit capture (a real PDF went from 3 of 11 matched to 11 of 11); route location waits went from 5s to 15s; Import Address List read settings.url instead of settings.supabaseUrl and failed every time.
  • Territory Map UX — Layer pills replaced by a Layers button and panel; action buttons rebuilt as a radial "+" hub with frosted backgrounds; the reload icon fixed; the BETA feedback button — whose protected-zones system had never been given any zones — now hides behind a new ModalVisibilityContext while sheets are open; Prospect Around's queue button, squashed by a flex: 1 style reused from a row layout, fixed. Screen transitions re-enabled as a crossfade.
  • Instrumentation — Sentry navigation breadcrumbs added so the still-unlocalized native "disabled" prop crash gets a screen trail when it recurs (production builds only).

Known issues carried forward: The native "disabled" prop crash (UnexpectedNativeTypeException) is still not localized to a screen. The cold-start "permission denied" timing issue from the last session may be related to the session-storage mismatch fixed here (a client with no session) — unconfirmed, needs field observation. Not yet field-verified: bulk address import (route and opportunity), the Google Drive image picker, and a second PDF territory pass. ModalVisibilityContext is wired into only two sheets. Left alone: src/utils/TerritoryMapScreen.js (121 KB, tracked, imported nowhere), the { ok: false } caller audit for branchTerritories, importedLists, nearbySearch, outreachUtils and socialEnrichment, and the tail of the ts-prune output.
