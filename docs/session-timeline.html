Session — Sep 23, 2026

Territory Tools & Outreach Automation

Continuing off the previous night's stability sweep, this session shipped BETA-67, then moved into a broad Territory Manager expansion — team ZIP roster import, a recovery tool for accidental imports, a genuine regression in the support/bug/feature-request email pipeline caught and fixed, outreach queueing that finally reaches every prospect in a batch instead of just the first, and a full bulk address-import feature (Excel, PDF, and photo/screenshot) for route planning and territory-filtered opportunity import.

What was done:

  • Team ZIP roster import — Parses a headerless, multi-block roster file (repeating ZIP/name column pairs, no headers) by detecting ZIP-shaped columns by content rather than label, matches the logged-in rep's first name, and shows a confirmation before adding anything. A companion "Remove Other Reps' ZIPs" tool recovers from an accidental full-file import without touching prior data.
  • Support/bug/feature email regression — Traced a months-old silent failure: a June 25 commit had switched BugReportScreen and FeatureRequestScreen from a real email-sending call to a database-only insert (for Roadmap tracking) without preserving the original notification. Restored the email alongside the existing DB write in both screens, and fixed SupportScreen's general contact form, which turned out to be entirely placeholder code that had never sent anything at all.
  • Outreach queueing — The "Reach Out" prompt after a batch save only ever offered the first reachable prospect, regardless of how many were saved; now queues every prospect with a phone/email and cycles through them. Extended to LeadLock's save flow, which never had an outreach prompt at all. Both now respect the same "Auto Intro Prompt" setting ReviewScreen already used, applied consistently across every capture method instead of just manual entry.
  • 90-day rolling weekly average — Territory Manager's heat map and ZIP list showed a raw single-week prospect count, which is noisy week to week; added a smoothed 90-day-total-divided-by-weeks average shown against the daily goal ×7.
  • Bulk address import — New feature accepting Excel/CSV, PDF, or a photo/screenshot of an address list. Extended the extract-prospect Edge Function with native PDF document support (Claude's Messages API accepts PDFs directly) and a new address-list extraction mode. Two entry points: route import (geocodes everything, orders via nearest-neighbor) and territory-filtered opportunity import (keeps only addresses in the rep's assigned ZIPs before geocoding). Both add results to the Prospect Queue and hand off to a new in-app route preview map (pins + route line) with Save for Later and Run Route (Google Maps handoff for the actual drive) — built as a standalone screen for now, planned to fold into TerritoryMapScreen during its future revamp.

Known issue carried forward: a real PDF-address-list test only matched 2 of roughly a dozen visible addresses against the rep's territory, despite the rep confirming all addresses should have matched — diagnostic logging was added but not yet resolved; needs the actual parsed-entry log output to determine whether this is a PDF-extraction miss or a filtering bug.
