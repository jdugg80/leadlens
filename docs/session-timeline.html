Session — Sep 25, 2026

Territory Map Overhaul — Branch Visibility, Live Compliance Data, Imported Lists & Prospect Around

The single largest session on this project to date, spanning the full Territory Map revamp originally scoped out and executed start to finish: same-branch ZIP visibility, a ground-up rebuild of the compliance/health signal pipeline onto real live data, a new private per-rep address-list feature, three rounds of nearby-search cost and reliability debugging, and the full "Prospect Around" feature — count, vertical, distance, and compliance-aware scoring, wired to both leads and imported addresses.

What was done:

  • Branch territory visibility — Same-branch reps' ZIPs now show as a read-only, color-coded, toggleable layer on the map, plus a full-roster publish option so branch-mates show up even if they haven't installed the app. Found and fixed along the way: removed ZIPs were never syncing off the server (so dropped ZIPs kept showing to other reps), a stale column name in territoryZipLoader, and missing `tappable` on ZIP polygons breaking Android taps.
  • Compliance/health signal rebuild — Diagnosed a genuinely tangled dormant pipeline: two overloaded database functions with the same name pointing at two different tables, one fed by a broken ingest function that hardcoded every record to the same coordinates, the other holding five stale hand-entered demo rows mistaken for live data. Rebuilt the real ingest path end to end — actual Houston Health Department data, Census Bureau geocoding tried first (free) with Google as a paid fallback, a pagination bug fixed, and a rolling-cursor cron job added so the data now refreshes automatically across the full ZIP roster without manual re-runs. Also fixed LensSignal map pins getting silently absorbed into generic lead-cluster bubbles, removed a React Native `Modal` component that violated the project's Android camera-conflict rule, and re-scoped the whole signal fetch from an arbitrary 25-mile radius to the rep's own assigned ZIPs.
  • Imported Address Lists — New feature: a rep can import a named list of addresses (e.g. every "CVS" in their territory) from a spreadsheet, PDF, or photo, geocoded server-side via a new Edge Function, shown as a private, toggleable, color-coded map layer that never auto-adds anything to the queue — items get added individually, on demand, from a detail card. Territory Manager gained a new "Lists" tab to hold this alongside the existing route/opportunity imports, replacing a single overcrowded tab with labeled sections.
  • Nearby-search cost and reliability — Three separate rounds of live-device debugging converged on real fixes: a Google Places field mask was requesting pricing-tier fields nothing used, an invalid legacy-API type value ('establishment') was silently failing every cheaper Nearby Search call and forcing a fallback to a 5x-costlier keyword search every time, a result-count parameter exceeded Google's actual limit, and a race between the map's animation and the real search center was zeroing out valid results. Also found and fixed two silent-filter incidents live with the user (a leftover "signals only" toggle and an unrelated business-type filter each independently zeroing a search with no visible explanation), which led to a new on-screen warning with a one-tap filter reset whenever active filters are hiding a search's results from the map.
  • Prospect Around — The session's headline feature: from a lead or an imported-list address, a rep can search a chosen radius for a chosen number of businesses, optionally scoped to one of six pest-relevant industry verticals (deliberately filtered server-side via Google's own place types, not as a client-side post-filter, to avoid repeating the exact silent-zero-result bug class found earlier in the same session), ranked by distance and by whether the business already has an active compliance signal, with an "exclude already-prospected" toggle and bulk add-to-queue. Along the way, found and fixed a pre-existing "Coming Soon" placeholder — the general nearby-discovery card's "Add to Queue" button had never actually worked — and built one shared queue-write implementation used by both it and the new feature.
  • Housekeeping — Cleaned up CHANGELOG.md (a leftover test entry, a session entry sitting in the wrong chronological position, a stray duplicate header) and ran this project's session-lockdown routine for the first time this session, surfacing and backfilling a previously undocumented gap (the Sep 24 SQLite build fix and BETA-68 release, below).

Known issue carried forward: an intermittent cold-start session-timing issue was observed live on device — Territory Map RPC calls occasionally return "permission denied" early in the boot sequence, traced to the app's Supabase session not yet being established at that point (confirmed the grants themselves are correct via a direct authenticated RPC call). Not yet root-caused as a reproducible app bug versus normal boot timing; needs monitoring.
